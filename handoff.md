**Build 1129 — mosh heals itself (2026-11-13):** Nate asked what else would make this more robust and said "do it all" to the list. The row is in `docs/bugs.md`. (1) A tab whose mosh-server is gone used to sit on "mosh: Last contact" for good. `MoshWatch` in `Blink/Commands/mosh/mosh.swift` now reads the tab's output (`TermDevice.outputObserver`), and when mosh's no-contact banner has ticked for 12 s (`MoshLiveness` in `FleetCore/MoshRules.swift`) it opens a TCP connection to the host's ssh port (`MoshParams.sshPort`); if the host answers, `MCPSession reconnectChild` ends the mosh and `_runCommand` runs its command again with no prompt in between. At most one a minute, never for a new client that has not heard from its server (UDP blocked), never while the host does not answer (phone offline). About 21 to 28 s from a dead server to the session being back. (2) The reconnect lands in the tmux session the tab was showing: the watcher keeps `MCPParams.reconnectSession` from the window title (`TmuxTitle`), and `MoshReconnect.command` turns plain `mosh host` into `mosh host -- tmux new-session -A -s <session>`, retargets `blink-attach <hex>`, and leaves other commands after `--` alone. Relaunch after a kill (1128) uses the same command. (3) Hosts: `MOSH_SERVER_NETWORK_TMOUT=259200` (3 days) in `~/.zshenv` on Ada (was 7 days since 2026-09-23) and Jarvis (was unset); `install-agent-loop.sh` adds it when unset, so Max gets it with the install it still needs. Servers already running keep the limit they started with. Verified in the simulator against a throwaway sshd on 127.0.0.1 and isolated tmux sockets (`tools/sim-mosh-restore.sh dead`): dead server, host down then up, killed while suspended, plain `mosh host`, switched session, idle. Not checked on a device (MANUAL-TESTS Feature Q). Limits: after a host restart a plain reconnect makes a bare tmux session (no `tm` setup, so no title and no agent features until `tm` runs there); a session name with spaces or punctuation outside `[A-Za-z0-9._-]` reruns the original command; a network that passes TCP to the host but drops UDP gets one useless reconnect. ## The build pipeline — `scripts/release.sh` (READ THIS before building)
One command: archives → symbol-guards → uploads → waits for ASC processing → attaches to the internal group, auto-bumping the build number from the ASC max. Critical hard-won flags it encodes:
- **`STRIP_STYLE=non-global` + `DEAD_CODE_STRIPPING=NO` + `BLINK_OTHER_LDFLAGS=-Wl,-export_dynamic`** — Blink dispatches built-in commands via `dlsym(RTLD_MAIN_ONLY, "<cmd>_main")`. The default `strip -all` deletes those symbols (only referenced by dlsym string), breaking EVERY built-in command at runtime (`config: command not found`). These flags keep them. **Symbol guard:** after archive, `xcrun dyld_info -exports .../Blink.app/Blink | grep -cE '_main$'` must be ≥ 22 (currently ~34 = 22 base + the added fleet/mount/PATH/notif commands).
- **`/usr/bin` ahead of PATH** for export — Homebrew `rsync 3.4.x` breaks Xcode's IPA packaging ("Copy failed"); Apple's openrsync works.
- Auth via the ASC API key (`-authenticationKey*`) so signing + upload are unattended.
- **release.sh runs detached via `nohup ... &`** in practice (long: ~15 min incl. ASC processing). To know when it's done, poll the log or run a background `until grep -qE "Attached build|FAILED" /tmp/release_*.log; do sleep 20; done`.

## Adding files to the Xcode project — `tools/add_to_target.py`
The high-level `mod-pbxproj add_file()` **crashes** on this SPM-heavy project (build files without `fileRef`). The helper uses the low-level object API instead. **Quirks:** NOT idempotent (its dup-check doesn't match) — always run on a clean pbxproj and add each file exactly once; verify with `grep -c "<File>.swift in Sources"` (expect 2 = build-file def + phase ref). It also cosmetically strips comment labels from `PBXFileSystemSynchronizedBuildFileExceptionSet` (Xcode 16 synced-folders); harmless. Always compile-verify after.
